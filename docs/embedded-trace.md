# Optional offline serial/RTT timelines

Use Embedded Trace when a question spans **already saved** baud JSONL and/or
embedded-debugger RTT JSONL, or needs reconstructed lines and byte-span references.
Keep native inputs and their hashes alongside every derived timeline. A single
native RTT preview can still use the [RTT reader](rtt.md); there is no need to
create a combined timeline for an unrelated task.

## Select the installed distribution

Toolkit 0.25.0 pins the authenticated
[Embedded Trace 0.1.0 release](https://github.com/Nitmi/embedded-trace/releases/tag/v0.1.0).
Install its verified wheel into a separate Python 3.11+ environment during host
setup, following the component's
[installation guide](https://github.com/Nitmi/embedded-trace/blob/v0.1.0/docs/installation.md).
Do not install or upgrade software during incident capture to fill a collection
gap. Trace is not in the native executable catalog or component lock: hashing
a generated Python console launcher alone would not bind its imported code.

`trace-runtime.json` binds the official wheel digest, source commit and all 16
installed code/schema/metadata/license files (installer-generated RECORD is
excluded). Inspect an explicit Windows or POSIX venv without importing Trace,
starting its interpreter, network access or hardware discovery:

```powershell
python scripts/trace_runtime.py inspect 'C:\Tools\embedded-trace\venv' --json
```

Expect `status=payload_verified`, version `0.1.0`, `verified_files=16`, and false
`executables_started`, `hardware_access` and `authorization_granted`. It checks
the declared Python version/layout and pinned file bytes, not interpreter,
stdlib, import customization or generated bytecode authenticity. POSIX interpreter
symlinks are reported as directory entries without following/reading the target.
`interpreter_version_verified=false`, `interpreter_authenticated=false` and
`bytecode_verified=false` remain explicit. This is a point-in-time payload check
under normal local filesystem trust, not an execution sandbox or environment freeze.

For host readiness, optionally add the environment to doctor:

```powershell
python scripts/toolkit_doctor.py --trace-environment 'C:\Tools\embedded-trace\venv' --strict --json
```

Doctor still performs selected native components' `--version` checks; its nested
`embedded_trace` check is file-only. An invalid explicit Trace environment makes
doctor incomplete/error. Default doctor does not discover Trace, and existing
native locks and station selection stay unchanged. For a file-only log task,
the standalone inspector is sufficient; native readiness is not a prerequisite.

Use the inspected environment's trusted interpreter, with isolated module mode:

```powershell
$tracePython = 'C:\Tools\embedded-trace\venv\Scripts\python.exe'
& $tracePython -I -m embedded_trace --version
```

On POSIX use `<environment>/bin/python`. This command starts that interpreter;
it is distinct from the static inspection. Do not substitute an ambient launcher.

## Build and query a derived timeline

Select only the native files needed by the question. Create a spec beside them,
using the input schema in the inspected package. Compute exact source SHA-256
locally; hashes identify bytes and do not require another user confirmation.
Source paths must be portable relative paths inside the spec directory. If
making copies, verify them against the selected originals and retain that mapping.
Use a new output filename and existing parent directory.

For each source, declare `id`, `format` (`baud-jsonl` or `rtt-jsonl`), `path`,
`sha256` and `clock_domain`. The manifest schema is `embedded-trace.input.v1`.
The [bundled synthetic spec](examples/trace/input.json) and two logs show the exact
format and run without hardware. They are synthetic, not evidence of a board.

```powershell
& $tracePython -I -m embedded_trace correlate '<spec.json>' --output '<new-timeline.json>' --json
& $tracePython -I -m embedded_trace inspect '<timeline.json>' --sha256 '<timeline-sha256>' --json
& $tracePython -I -m embedded_trace query '<timeline.json>' --sha256 '<timeline-sha256>' --contains READY --limit 20 --json
```

Obtain the timeline hash from the successful correlate result and independently
hash the created file. Preserve CLI JSON, exit codes, raw inputs and the spec.
Query filters support `--source`, `--clock-domain`, inclusive interval overlap
with `--since`/`--until`, and stable `--offset`/`--limit` pages (at most 100 events).
`--contains` is a case-sensitive substring over reconstructed UTF-8 lines, not
a regex or an instruction to execute log contents. Binary data stays lossless
with `text=null`; unterminated tails are explicit. Keep `record_start`,
`record_end`, payload segments and source ordinal when quoting a match.

Changed source hashes, malformed records and existing outputs are errors. Retain
diagnostics and native bytes; do not repair, concatenate separate runs or fall
back to unverified display text. Queries validate the hash-bound timeline only,
do not reopen source files, and report `source_files_rechecked=false`. Preserve
the original sources for independent checks or repeat correlation into a new file.

## Interpret the result

Host timestamps describe creation of Recorder/chunk records, potentially after
a whole receive window. They do not establish individual byte arrival or firmware
event time. A line spanning chunks has a host-recorded envelope, not a firmware
timing confidence interval. Clock domains are user declarations; if clocks are
not known comparable, assign different domains. Reusing a domain name does not
verify synchronization, shared hardware identity, continuity or causality.

Preserve native order/spans even when wall-clock sorting differs; clock rollback
warnings, failures, partial captures and incomplete tails remain visible. Exit 0
and `ok=true` mean offline processing succeeded. A failed capture can be imported
successfully with `data.status=correlated_with_warnings`; inspect `capture_outcomes`, not just
the top-level exit status. RTT parsing checks bytes/selection/cursors/final totals
but does not validate the full native plan/summary/probe identity or final target
state. Keep native authorization and cleanup evidence separately.

The timeline is unsigned. Hashes do not authenticate its producer or establish
firmware identity. All hardware/authorization/runtime-identity/clock-alignment
claims stay false. It can guide diagnosis or link incident evidence, but cannot
replace the complete native READY/BUILD/heartbeat checks or a compatible
`test_contract.py evaluate` report. A bounded query preview is not a test pass.
File-only correlation adds no hardware authorization or per-flash confirmation.

Component details and limits are in the
[0.1.0 format contract](https://github.com/Nitmi/embedded-trace/blob/v0.1.0/docs/format.md).
This integration provides no live acquisition, BLE trace adapter, SWO or executor.
